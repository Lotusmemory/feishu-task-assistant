## 项目目标

构建一个供公司内部员工使用的 AI 智能客服：

- 通过飞书应用机器人接收问题。
- 使用 MiniMax M3 生成回答。
- 使用飞书多维表格 Base 管理内部知识和未知问题。
- 使用 SiliconFlow `BAAI/bge-m3` 生成向量。
- 通过 RAG 仅依据状态为“已发布”的知识回答。
- 无法回答时安全拒答并记录未知问题。
- 员工明确要求回访时记录其飞书身份。
- 管理员通过飞书交互卡片补充知识，无需手工创建 Base 行。

## 当前缺陷

管理员发送 `补充知识：...` 时，机器人会把它当作普通 RAG 问题，尚不具备知识录入命令或卡片流程。

MiniMax 回复曾暴露 `<think>...</think>` 内部推理内容。实现卡片功能时必须统一过滤所有面向用户的模型输出，包括普通问答、RAG 回答和快速知识整理结果。

## 已批准的卡片设计

### 权限

只有以下两位管理员可以打开、提交、保存和发布知识卡片：

- 当前用户本人。
- 吴雷鸣。

吴雷鸣已通过飞书通讯录唯一匹配到已激活账号。运行时必须使用 `open_id` 白名单，不得按姓名判断。具体 ID 应从安全配置读取，不要写入文档、日志或面向用户的回复。

每个卡片动作都必须重新检查操作者权限，防止转发卡片绕过权限。

### 入口卡片

管理员发送：

```text
补充知识
```

机器人返回入口卡片：

- 快速录入
- 完整录入
- 取消

### 快速录入

管理员填写：

- 原始知识
- 来源链接

MiniMax 自动整理：

- 标题
- 分类
- 适用问题
- 正文
- 关键词

模型只能整理表达，不能补造联系人、公司制度、链接或流程事实。

### 完整录入

管理员直接填写：

- 标题
- 分类
- 适用问题
- 正文
- 关键词
- 来源链接

完整录入只做必要的空白清理和字段校验，不改写事实内容。

### 预览卡片

两种录入方式都进入同一个预览卡片，提供：

- 确认发布
- 保存待审核
- 返回修改
- 取消

### 来源和发布规则

- 来源链接必须是合法的 HTTP 或 HTTPS 地址。
- 没有有效来源链接时，可以保存为“待审核”，但不能发布。
- 保存待审核后不进入 RAG 索引。
- 确认发布后写入 Base 为“已发布”，并立即同步索引。
- 重复点击发布最多创建一条 Base 记录。
- 临时卡片草稿可以在服务重启后失效；已写入 Base 的记录不能丢失。

## 实施成功标准

1. 当前用户和吴雷鸣能打开快速录入和完整录入卡片。
2. 普通员工无法创建、保存或发布知识。
3. 快速录入能生成完整且不编造事实的预览。
4. 完整录入保持管理员填写的事实内容。
5. 无有效来源可以保存待审核，但不能发布。
6. 发布后 Base 只新增一条记录，并立即进入 RAG 索引。
7. 重复点击发布不会重复写入。
8. 转发卡片不能绕过权限。
9. 所有机器人回复不再显示 `<think>` 内容。
10. 现有普通问答、未知问题和回访功能不回归。
