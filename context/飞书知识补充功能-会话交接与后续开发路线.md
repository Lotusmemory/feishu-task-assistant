# 飞书知识补充功能：会话交接与后续开发路线

更新时间：2026-07-14（Asia/Shanghai）

## 1. 项目目标

在现有飞书 + MiniMax 内部客服机器人中，为指定管理员提供“补充知识”卡片工作流。管理员可通过快速录入或完整录入生成知识预览，随后发布到飞书 Base 或保存为待审核。已发布知识会同步到本地向量索引，供 RAG 问答使用。

## 3. 已确认的产品规则

1. 只有配置在 `KNOWLEDGE_ADMIN_OPEN_IDS` 中的一至两位管理员可以补充、保存或发布知识。
2. 每次卡片动作都重新校验操作者身份，不能只在入口校验。
3. 管理员发送精确文本 `补充知识` 后进入卡片流程。
4. 快速录入：管理员填写原始知识，MiniMax 只整理标题、分类、适用问题和关键词；正文必须保留管理员提交的原文，不能采用模型扩写。
5. 完整录入：不调用 MiniMax，只清理首尾空白并校验必填字段。
6. 来源链接为可选项；为空时允许发布，非空时必须是有效 HTTP/HTTPS 地址。
7. 可选择“确认发布”“保存待审核”“返回修改”或“取消”。
8. 发布只允许写入一次；重复点击不能产生重复 Base 记录。
9. Base 写入成功即视为发布成功；向量索引同步失败不能回滚已发布记录，由定时同步继续重试。
10. 服务重启后，尚未写入 Base 的内存草稿可以失效；旧卡片应提示重新发送 `补充知识`。

## 4. 已实现功能

### 4.1 卡片流程

- 补充知识入口卡片：快速录入、完整录入、取消。
- 快速录入表单：原始知识、可选来源链接。
- 完整录入表单：标题、分类、适用问题、正文、关键词、可选来源链接。
- 知识预览卡片：确认发布、保存待审核、返回修改、取消。
- 成功、失败、处理中状态卡片。
- 飞书 JSON 2.0 卡片回调响应使用官方要求的封装：`card.type = raw`，`card.data` 为卡片 JSON。

### 4.2 快速录入的超时处理

飞书卡片回调必须在 3 秒内完成。MiniMax 有时超过 3 秒，因此快速预览已改成两阶段：

1. 点击“生成预览”后立即返回“正在整理知识”。
2. 后台调用 MiniMax。
3. 成功后通过消息更新接口把卡片替换为知识预览。
4. 失败后恢复快速录入表单，保留原始输入并显示错误，允许直接重试。

### 4.3 发布的超时处理

向量生成和索引保存可能超过飞书 3 秒限制，因此发布流程已解耦：

1. 先写入 Base。
2. Base 成功后立即返回“已发布，知识索引正在同步”。
3. 后台立即同步向量索引。
4. 同步失败时记录失败状态；现有五分钟定时同步负责恢复。

### 4.4 MiniMax 输出兼容与事实保护

- 移除 `<think>` 隐藏推理内容。
- 接受被 Markdown `json` 代码围栏包裹的 JSON。
- 将模型返回的 `questions` 数组规范化为换行字符串。
- 将模型返回的 `keywords` 数组规范化为逗号字符串。
- 强制将知识正文设置为管理员提交的原文，避免模型扩写成为未经确认的公司制度。
- 继续校验标题、分类、问题、正文和关键词；分类只允许 `HR`、`行政`、`IT`、`业务流程`、`其他`。

### 4.5 Base 与索引

- Base 支持创建“已发布”或“待审核”知识记录。
- 可选来源为空时不写来源字段。
- 发布时记录提交人和审核人身份。
- 仅“已发布”记录进入向量索引。
- 发布后启动一次后台全量索引同步，另有五分钟定时同步。

## 5. 本轮已定位并修复的问题

1. 表单缺少 `name`、下拉组件包含不支持的 `label`，导致飞书错误码 200671。
2. 点击按钮卡片一闪后恢复：回调更新方式与空响应发生竞态。
3. 点击无反应：新版回调缺少 `{ card: { type: "raw", data: ... } }` 封装。
4. 快速整理失败：MiniMax 返回 fenced JSON，且问题和关键词可能为数组。
5. 无来源无法发布且错误卡片无按钮：来源规则改为可选，非法非空链接提前拦截。
6. 第一次发布回调超时、第二次成功：向量同步阻塞回调，现已后台化。
7. 快速生成预览偶发回调超时：MiniMax 阻塞回调，现已改为处理中卡片 + 后台更新。

## 6. 当前已知限制与风险

1. 草稿只保存在进程内存中，服务重启后未提交草稿丢失。
2. 后台快速整理依赖消息卡片更新接口；需要继续实机验证慢请求、失败恢复和连续点击。
3. 发布卡片显示“正在同步”后不会主动二次刷新为“同步完成”；实际索引会在后台更新。
4. 当前索引同步是全量重建；知识量增大后，发布延迟、API 调用量和并发覆盖风险会上升。
5. 当前修改尚未提交，意外删除工作树会丢失本轮代码。
6. 目前管理员上限固定为两人，尚无角色分级、审核队列或后台配置界面。
7. 错误日志仍以开发日志为主，缺少统一的请求 ID、耗时指标和告警。

## 8. 后续开发路线图

### P0：稳定性与可交付性

#### 8.1 完成端到端实机验收并提交代码

目标：把当前“本地已验证”推进到“飞书真实链路已验证、代码已安全保存”。

成功标准：

- 快速录入、完整录入、保存待审核、发布、修改、取消均实机通过。
- 慢 MiniMax 请求不触发回调超时。
- 重复发布只产生一条 Base 记录。
- 普通问答可命中新发布知识。
- `npm test`、语法检查、差异检查通过。
- `.env`、真实 `open_id` 和密钥未进入提交。
- 形成一个边界清晰的 Git 提交；是否推送由用户确认。

#### 8.2 增加回调耗时与阶段日志

目标：能快速区分飞书回调、MiniMax、Base、向量服务和卡片更新哪个阶段变慢或失败。

建议记录：事件 ID/消息 ID 的脱敏摘要、动作名、阶段、耗时、结果、错误类型；禁止记录原始知识、密钥和完整身份 ID。

成功标准：一次失败可以从日志定位到具体外部依赖和阶段，不再只看到统一错误文案。

#### 8.3 后台任务可靠队列

目标：避免进程在 MiniMax 整理或索引同步期间重启导致任务静默丢失。

最小方案：在 Base 增加处理状态或任务表，记录 `pending/running/succeeded/failed`、重试次数和最后错误；启动时扫描未完成任务继续处理。

成功标准：在后台整理或同步中途强制重启服务，任务能自动恢复或明确进入可重试状态。

### P1：审核与知识治理

#### 8.4 待审核队列卡片

目标：管理员能在飞书中查看待审核知识并执行批准、驳回、修改。

成功标准：

- 支持分页查看待审核记录。
- 批准后状态变为已发布并触发索引同步。
- 驳回必须填写原因，并保留审计记录。
- 重复操作幂等。

#### 8.5 知识版本与审计记录

目标：修改已发布知识时保留历史版本，能追踪谁在何时改了什么。

成功标准：每次修改生成新版本；可查看版本列表、差异、提交人、审核人、时间和状态；支持回滚到指定历史版本。

#### 8.6 知识下线与恢复

目标：管理员可以停用错误或过期知识，并让其立即退出 RAG 索引。

成功标准：下线操作幂等；Base 状态和索引一致；支持恢复；所有操作有审计记录。

#### 8.7 重复与冲突检测

目标：发布前提示与现有知识高度相似或内容冲突的记录，减少重复制度。

实现建议：标题/关键词规则检索 + 向量相似度召回；只提供候选和差异，不让模型自行裁决制度冲突。

成功标准：预览卡片列出相似知识、相似度和来源，管理员可选择继续发布、合并或取消。

### P1：体验优化

#### 8.8 发布和同步状态主动刷新

目标：发布卡片从“正在同步”自动更新为“已同步”或“同步失败，可重试”。

成功标准：后台同步完成后更新原卡片；失败时提供“重试同步”按钮；重复点击不会并发重建多份索引。

#### 8.9 草稿持久化与继续编辑

目标：服务重启或用户暂时离开后仍能恢复未完成录入。

成功标准：草稿有过期时间；管理员可查看“我的草稿”；恢复时重新校验权限；完成或取消后不能继续编辑。

#### 8.10 分类与字段配置化

目标：分类不再硬编码，并支持按业务需要调整知识字段。

原则：在确有多个部门需求后再做，避免为未来假设引入过早抽象。

成功标准：分类来源单一、修改后卡片与校验同时生效、旧记录兼容。

### P2：检索质量与运营

#### 8.11 增量索引更新

目标：发布、修改或下线单条知识时只更新相关向量，避免每次全量重建。

成功标准：单条变更不会影响无关索引；并发更新有串行化或版本检查；失败可重放；定时全量校准仍保留为兜底。

#### 8.12 检索质量评测集

目标：用固定问题集衡量召回率、误答率、拒答质量和来源展示。

成功标准：至少覆盖每个分类、同义问法、冲突资料、无答案问题和过期资料；每次调整阈值、切分或模型前后可对比。

#### 8.13 未命中问题闭环

目标：把高频未知问题转化为待补充知识建议。

成功标准：按规范化问题聚合次数；管理员可从问题卡片一键进入快速录入；发布后关联问题标记为已解决。

#### 8.14 知识健康度看板

目标：识别长期未更新、无来源、高频命中、低反馈和冲突知识。

成功标准：指标定义可解释；看板只提供治理线索，不自动删除或修改知识。

### P2：权限与安全

#### 8.15 角色分级

目标：区分录入者、审核者和知识管理员，而不是所有管理员都可直接发布。

成功标准：权限在每次动作时校验；转发卡片不能绕过；角色变更即时生效；拒绝操作有清晰提示。

#### 8.16 敏感信息与提示注入防护

目标：避免将密钥、个人敏感信息或原始知识中的恶意指令带入模型和日志。

成功标准：日志脱敏；输入长度限制；模型提示明确把原始知识视为数据而非指令；测试覆盖提示注入、脚本链接和异常长输入。

## 9. 推荐实施顺序

1. P0 实机验收、日志、提交与备份。
2. 后台任务可靠队列。
3. 待审核队列、版本审计、知识下线。
4. 主动同步状态与草稿持久化。
5. 重复冲突检测和未命中问题闭环。
6. 增量索引、评测集和健康度看板。
7. 有明确组织需求后再做角色分级和字段配置化。

每个功能继续采用有限闭环：定义成功标准 → 先写复现/验收测试 → 最小实现 → 相关测试和实机验证 → 依据证据修正 → 完成或明确停止条件。

## 11. 交接结论

当前核心知识补充流程已实现，并针对飞书 3 秒回调限制完成两处关键异步化：快速预览和发布后索引同步。自动测试已通过，但最新两阶段快速预览仍需要一次完整飞书实机验收。验收通过后，最优先动作不是继续扩功能，而是检查敏感信息、提交当前分支并按用户授权备份，先把已完成成果稳定保存。
