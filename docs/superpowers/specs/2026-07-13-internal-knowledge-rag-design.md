# 飞书内部员工知识助手 RAG 设计

## 目标

将现有飞书 MiniMax M3 机器人升级为公司内部员工知识助手。员工通过私聊或群聊 `@机器人` 查询 HR、行政、IT 和业务流程攻略；系统只依据管理员已审核发布的内部知识回答，并提供可追溯来源。

当前没有可用内部资料，因此第一阶段同时建设知识模板和未知问题收集机制，帮助团队逐步形成知识库。

## 成功标准

- 员工能够向飞书 Base 提交候选知识，只有管理员审核为“已发布”的内容进入检索。
- 已发布知识经过本地嵌入模型向量化，员工换一种问法仍能检索到相关内容。
- 回答先给结论，再给步骤和注意事项，并附知识标题、更新时间和来源链接。
- 低相关度或无知识命中时不编造公司制度，而是记录待补问题。
- 待补问题默认匿名；员工明确要求回访时才记录身份。
- Base 暂时不可用时继续使用最后一次成功索引。
- 知识修改或下线后，旧片段不会继续参与回答。

## 范围

### 包含

- 飞书 Base 知识库与待补问题池
- 管理员审核发布流程
- 本地文本嵌入模型
- 本地向量索引
- 定时知识同步
- 基于检索内容的 MiniMax M3 回答
- 来源引用、拒答和未知问题记录

### 不包含

- 图片、PDF、Word 自动解析
- Base 实时事件监听
- 对话长期记忆
- 多租户和复杂权限体系
- 员工提交内容自动发布
- 独立管理后台

## 系统架构

### 问答链路

1. 员工在飞书中私聊机器人，或在群聊中 `@机器人`。
2. 现有消息策略完成文本过滤和事件去重。
3. 本地嵌入模型将员工问题转换为向量。
4. 本地向量索引检索相关度最高的三个知识片段。
5. 系统执行相关度门槛判断：
   - 命中时，将知识片段和元数据交给 MiniMax M3 组织答案。
   - 未命中时，不调用 MiniMax 生成制度答案，转入未知问题流程。
6. 命中回答附知识标题、更新时间和来源链接。

### 知识同步链路

1. 员工在飞书 Base 提交候选知识，状态默认为“待审核”。
2. 管理员审核、修订，并将状态改为“已发布”。
3. 机器人启动时全量读取一次已发布知识，运行中每五分钟增量检查更新时间。
4. 同步器按标题与段落切分正文，生成嵌入向量，并构建新索引。
5. 新索引完整生成后原子替换当前索引。
6. 修改、下线或删除条目时，旧条目的全部片段从新索引中移除。

飞书 Base 是事实来源。本地索引是可重新生成的缓存，不是唯一数据源。

## 飞书 Base 数据模型

### 知识库表

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| 标题 | 单行文本 | 必填，知识条目名称 |
| 分类 | 单选 | HR、行政、IT、业务流程、其他 |
| 适用问题 | 多行文本 | 员工可能采用的典型问法 |
| 正文 | 多行文本 | 管理员审核后的完整攻略 |
| 关键词 | 多选或文本 | 用于检索补强和运营维护 |
| 来源链接 | URL | 制度原文或流程入口 |
| 状态 | 单选 | 待审核、已发布、已下线；仅已发布可用于回答 |
| 更新时间 | 最后更新时间 | 用于增量同步和回答引用 |
| 提交人 | 人员 | 审核追踪，不展示给提问者 |
| 审核人 | 人员 | 发布责任人，不展示给提问者 |

### 待补问题表

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| 原始问题 | 多行文本 | 仅保留完成问题处理所需内容 |
| 归一化问题 | 单行文本 | 去除不必要的姓名、项目名等识别信息 |
| 分类 | 单选 | HR、行政、IT、业务流程、其他 |
| 出现次数 | 数字 | 重复问题累计，不重复创建记录 |
| 首次提问时间 | 日期时间 | 首次出现时间 |
| 最后提问时间 | 日期时间 | 最近出现时间 |
| 状态 | 单选 | 待补充、处理中、已解决、忽略 |
| 是否要求回访 | 复选框 | 默认否 |
| 回访用户 | 人员或文本 | 仅员工明确要求回访时填写 |
| 关联知识 | 关联记录 | 问题解决后关联知识库条目 |

## 审核与权限原则

- 员工可以提交候选知识，但不能让候选知识直接参与回答。
- 管理员负责审核、修订和发布。
- 机器人只读取状态为“已发布”的条目。
- 提交人和审核人仅用于治理，不在机器人回答中展示。
- Base 访问凭证和表标识通过环境变量配置，不写入代码或 Git。

## 嵌入与向量索引

### 嵌入模型

实施验证发现当前网络无法可靠下载本地模型所需的完整 Hugging Face/Xet 文件。经用户确认，正式方案改用硅基流动 `BAAI/bge-m3` Embeddings API。已发布知识片段会发送给硅基流动生成向量，MiniMax 仍只负责基于命中片段生成最终回答。

该模型已通过 12 组中文内部流程样本验证，Top-1 命中 12/12；已知问题最低正确分数为 0.621，未知问题最高分数为 0.418，默认拒答门槛取 0.52。运行配置必须满足：

- 支持中文语义检索。
- 使用 `https://api.siliconflow.cn/v1/embeddings`。
- 模型名固定为 `BAAI/bge-m3`。
- API Key 仅保存在 `.env`。
- 公司在录入真实内部知识前确认向硅基流动发送文本符合数据治理要求。

### 知识切分

- 优先按标题和自然段落切分。
- 单个片段过长时，按约 500–800 个中文字符进一步切分。
- 相邻长片段保留少量重叠上下文。
- 每个片段携带：知识记录 ID、标题、分类、更新时间、来源链接和片段序号。
- `适用问题`、标题、关键词和正文共同用于生成检索文本，回答上下文只使用审核后的正文及必要元数据。

### 检索

- 问题向量与索引片段计算相似度。
- 默认最多返回三个片段。
- 使用可配置但有明确默认值的相关度门槛；门槛必须通过中文测试集校准，不凭感觉设定。
- 多个片段来自同一知识条目时允许合并，避免重复引用。
- 本地索引更新采用完整构建后原子替换，查询永远使用完整索引。

## 回答规范

1. 先直接回答结论，再给步骤和注意事项。
2. 只允许依据检索到的已发布知识回答公司制度和流程。
3. 不得把模型通用常识表述成公司规定。
4. 多条知识冲突时，不自行裁决；指出冲突并建议联系知识维护人。
5. 资料包含适用范围、生效日期或例外条件时必须在回答中体现。
6. 结尾列出知识标题、最后更新时间和来源链接。
7. 不向员工展示内部推理、向量分数、提交人或审核人。
8. 与内部工作攻略无关的问题，简短说明服务范围。

## 未知问题流程

- 低于检索门槛时，机器人明确说明“当前知识库暂无此信息”。
- 默认匿名记录问题，不写入员工身份。
- 机器人询问员工是否需要回访；只有员工明确要求时才记录回访身份。
- 写入前生成归一化问题，用于匹配已有待补记录。
- 命中已有归一化问题时增加出现次数并更新最后提问时间。
- 未知问题写入失败时，仍然拒绝编造，同时提示本次问题未成功记录。
- Base 没有任何已发布内容时，机器人进入知识收集模式，只记录未知问题。

## 故障处理

- 嵌入模型下载或加载失败：提示知识检索暂不可用，不退化为无依据回答。
- Base 权限、表或必需字段缺失：启动检查失败并列出缺失配置。
- Base 临时不可用：继续使用最后成功索引，并记录告警。
- 本地索引损坏：从 Base 全量重建。
- MiniMax 请求失败：回复现有通用错误信息，不暴露内部响应或凭证。
- 待补问题写入失败：说明未成功记录，但不影响安全拒答。

## 测试与验收

### 自动化测试

- 知识状态过滤：待审核和已下线条目不进入索引。
- 段落切分、长文本切分和元数据保留。
- 相似度排序、Top 3 限制和门槛拒答。
- 来源标题、更新时间和链接拼装。
- MiniMax 只接收命中的已发布知识片段。
- 未命中时不调用 MiniMax 生成制度答案。
- 匿名问题不写身份，明确要求回访时才写身份。
- 归一化重复问题合并并累计次数。
- 新增、修改和下线知识后的索引变化。
- Base 暂时不可用时继续使用最后成功索引。
- 索引原子替换和损坏重建。

### 人工验收

1. 已知问题能得到带来源的正确回答。
2. 同一问题换一种自然语言表达仍能命中。
3. 未知问题被安全拒答并匿名记录。
4. 员工明确要求回访后才记录身份。
5. 知识下线后不再被引用。
6. 冲突知识不会被机器人擅自裁决。
7. Base 短暂不可用时仍能依据最后索引回答。

## 配置边界

实施阶段需要增加 Base 标识、表标识、同步间隔、本地模型缓存目录和索引路径等配置。仅对部署环境不同或确有运营价值的参数开放配置；Top K 固定为 3，除非测试证据证明需要调整。
