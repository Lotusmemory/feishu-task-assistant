# 飞书卡片补充知识库设计

## 目标

允许指定管理员直接在飞书机器人会话中通过交互卡片补充知识，不再手工进入 Base 创建记录。发布后的知识立即进入现有 RAG 索引，同时保持来源可追溯和发布权限可控。

## 范围

本次只增加知识录入、预览、保存待审核和发布流程，并修复模型回复中的 `<think>` 内容泄露。不增加知识版本管理、多人会签、撤回发布、批量导入或飞书卡片后台管理页面。

## 权限

- 发布白名单只包含当前管理员和通讯录中唯一匹配的吴雷鸣。
- 白名单使用飞书 `open_id` 配置，不使用姓名进行运行时判断。
- 打开卡片、提交表单、保存待审核和确认发布时都重新检查操作者身份。
- 非白名单员工发送“补充知识”时，只返回无权限提示，不生成草稿、不写 Base。
- 卡片被转发后，非白名单员工仍不能执行任何写操作。

## 用户流程

### 入口卡片

白名单管理员向机器人发送“补充知识”，机器人返回入口卡片，提供：

1. 快速录入
2. 完整录入
3. 取消

### 快速录入

卡片包含两个输入项：

- 原始知识
- 来源链接

提交后，MiniMax 将原始知识整理为标题、分类、适用问题、正文和关键词。分类限定为现有 Base 选项：HR、行政、IT、业务流程、其他。

### 完整录入

卡片直接收集：

- 标题
- 分类
- 适用问题
- 正文
- 关键词
- 来源链接

完整录入不要求模型重写管理员填写的事实内容，只做必要的空白清理和字段校验。

### 预览卡片

两种录入方式提交后都进入同一预览卡片，完整展示最终字段，并提供：

- 确认发布
- 保存待审核
- 返回修改
- 取消

“返回修改”恢复当前草稿和原录入模式，避免重新填写。

### 保存和发布

- “保存待审核”写入 Base，状态为“待审核”，不进入 RAG 索引。
- “确认发布”要求来源链接为合法的 HTTP 或 HTTPS 地址；缺失或格式不合法时拒绝发布，并保留草稿供修改。
- 发布成功后写入 Base，状态为“已发布”，记录实际审核人的飞书身份，并立即触发现有知识索引同步。
- 机器人用成功卡片返回知识标题、Base 记录标识和同步结果。

## 状态和并发

- 每张预览卡片绑定唯一、不可由客户端自行替换的草稿标识。
- 草稿在服务端保存，卡片只携带关联标识，不信任客户端回传的知识正文或权限信息。
- 发布动作具有幂等性：同一草稿重复点击“确认发布”最多产生一条 Base 记录。
- 已取消、已发布或已保存的草稿不能再次提交。
- 服务重启后，已经写入 Base 的记录不会丢失；尚未保存或发布的卡片草稿可以失效，并明确提示管理员重新发起，避免为一次性交互增加额外持久化机制。

## Base 写入

沿用现有“知识库”表及字段：标题、分类、适用问题、正文、关键词、来源链接、状态、更新时间、提交人和审核人。机器人不新增表和字段。

- 快速录入和完整录入在预览阶段不写 Base。
- 点击“保存待审核”或“确认发布”时才创建记录。
- Base 写入失败时不触发索引同步，卡片显示可重试错误。
- 索引同步失败时保留已发布记录，并明确提示“已发布但同步失败”，由现有定时同步机制恢复。

## 模型输出处理

- 快速录入要求 MiniMax 返回结构化知识字段；解析失败时提示管理员修改原始知识后重试，不写 Base。
- 所有面向员工和管理员的模型文本，在发送飞书前统一移除 `<think>...</think>` 区块及遗留标签。
- 模型只负责整理表达，不负责补造联系人、制度、链接或操作步骤。

## 飞书事件集成

- 现有文本消息事件继续负责识别“补充知识”入口。
- 新增飞书卡片交互回调处理，按动作标识路由入口选择、表单提交、返回修改、保存和发布。
- 回调处理沿用现有 WebSocket 服务；若飞书应用尚未订阅卡片交互事件，需要在开发者后台增加对应事件并重新发布应用版本。
- 回调响应应及时返回，耗时的模型调用、Base 写入和索引同步在允许的回调时限内处理，并向用户展示明确的处理中或结果状态。

## 错误处理

- 无权限：拒绝并不写入。
- 必填字段缺失：在卡片中指出缺失字段。
- 来源链接无效：允许保存待审核，禁止发布。
- 模型整理失败：保留原始输入并允许重试。
- Base 写入失败：不改变草稿终态，允许重试。
- 重复点击：返回既有结果，不重复创建记录。
- 过期卡片：提示重新发送“补充知识”。

## 验收标准

1. 当前管理员和吴雷鸣均能打开快速录入与完整录入卡片。
2. 其他员工无法创建、保存或发布知识。
3. 快速录入能生成完整预览，完整录入能原样保留事实内容。
4. 无有效来源链接时可以保存待审核，但不能发布。
5. 确认发布后 Base 只新增一条“已发布”记录，并立即同步到 RAG 索引。
6. 重复点击发布不会产生重复记录。
7. 卡片转发不绕过发布权限。
8. 普通问答、未知问题记录和回访标记功能保持通过。
9. 所有机器人回复都不再展示 `<think>` 内容。

## 验证方式

- 单元测试覆盖权限判断、命令路由、字段校验、结构化输出解析、草稿状态转换、幂等发布和 `<think>` 过滤。
- 集成测试使用伪造飞书事件验证卡片动作到 Base 客户端调用及索引同步的完整路径。
- 本地运行全部现有测试、语法检查和依赖安全检查。
- 在飞书中分别用管理员、吴雷鸣和普通员工账号完成权限验收，再完成快速录入、完整录入、待审核、发布、重复点击和检索复测。
