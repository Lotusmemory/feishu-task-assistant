# 飞书客服与任务助理使用说明

适用应用：飞书客服与任务助理
适用版本：`0.1.0`
更新日期：2026-07-15

## 1. 应用简介

飞书客服与任务助理是一个运行在飞书中的内部智能客服机器人，主要提供四类能力：

1. 根据已发布的内部知识回答问题。
2. 通过自然语言创建、查看、修改和删除任务。
3. 每天 18:00 发送任务盘点卡片，并向 Leader 提供只读汇总。
4. 在用户主动请求且具备授权时，总结当天或指定日期范围的聊天记录。

应用不会把知识库中没有的公司制度交给模型自由编造。无法从已发布知识中找到答案时，会明确提示知识库暂未覆盖，并将问题匿名记入待补清单。

## 2. 使用入口

### 2.1 私聊机器人

推荐在与智能客服的私聊中使用。

私聊支持：

- 内部知识问答。
- 创建、查询、修改和删除任务。
- 查看自己的任务。
- 请求聊天总结。

### 2.2 群聊中使用

群聊中必须 `@智能客服` 后再输入问题，例如：

```text
@智能客服 年假应该怎么申请？
```

没有 `@智能客服` 的普通群消息会被忽略。

群聊适合知识问答，不建议在群聊中操作私人任务或请求私人聊天总结。私人聊天总结应始终在私聊中发起。

### 2.3 支持的消息类型

当前只处理文本消息。

以下消息不会作为客服问题或聊天总结正文处理：

- 图片。
- 文件。
- 语音。
- 视频。
- 飞书卡片中的非文本资源。
- 空消息。

## 3. 内部知识问答

### 3.1 普通提问

可以直接使用自然语言提问：

```text
年假应该怎么申请？
```

```text
办公电脑无法连接 Wi-Fi 怎么办？
```

```text
报销需要准备哪些材料？
```

机器人只会依据飞书 Base 中状态为“已发布”的知识条目回答，并在有来源信息时附上相关来源。

### 3.2 知识库暂未覆盖

如果没有找到足够相关的已发布知识，机器人会返回类似提示：

```text
当前知识库暂无此信息。我已将问题记入待补清单；如需人工回访，请发送“需要回访：你的问题”。
```

此时系统会匿名记录问题，方便管理员补充知识。

### 3.3 请求人工回访

如果希望管理员根据你的身份进行回访，请使用固定格式：

```text
需要回访：完整早报打开报错，应该怎么处理？
```

只有明确以 `需要回访：` 开头时，系统才会将回访请求与发送者身份关联。

普通知识问答和匿名待补问题不会主动记录回访身份。

## 4. 创建任务

### 4.1 创建自己的任务

可以直接发送：

```text
创建任务 喝水
```

也可以使用更自然的表达：

```text
帮我创建一个任务：完成首页设计
```

```text
新增任务 整理周报
```

如果没有提供任务名，机器人会发送“创建任务”表单卡片，请在卡片中补充：

- 任务名。
- 优先级。
- 截止时间。

### 4.2 创建时指定日期或状态

示例：

```text
创建任务 完成测试 截止明天
```

```text
创建任务 整理需求 现在开始
```

```text
创建任务 发布公告 状态为进行中
```

系统会识别明确写出的任务名、状态和日期。未填写的字段会按当前任务规则补充默认值。

### 4.3 为其他成员创建任务

示例：

```text
帮田嘉国创建一个任务：检查发布清单
```

```text
帮董亚思创建任务 喝水
```

系统会根据成员表解析负责人姓名。

如果同名成员不止一人或无法唯一确定负责人，系统不会猜测，而会提示无法唯一确定。

### 4.4 创建前确认

创建任务不会直接写入任务 Base。

机器人会先发送“确认任务操作”卡片，展示任务预览。请检查内容后选择：

- `确认`：正式创建任务。
- `取消`：放弃本次操作。

确认操作具有幂等保护，同一条确认不会重复写入任务表。

## 5. 查看任务

### 5.1 查看自己的任务

发送：

```text
查看我的任务
```

也可以发送：

```text
查询我的任务
```

```text
盘点我的任务
```

```text
列出我的任务
```

机器人会返回“我的任务盘点”卡片，展示匹配任务的：

- 任务名。
- 状态。
- 优先级。
- 进度。
- 截止时间。

如果没有匹配任务，会明确回复“没有找到匹配的任务”。

## 6. 修改任务

### 6.1 未指定任务名

发送：

```text
修改任务
```

或：

```text
帮我修改任务
```

机器人会查询当前发送者负责、且状态属于以下范围的任务：

- 未开始。
- 进行中。
- 阻塞中。
- 已延期。

然后发送“选择要修改的任务”卡片。点击目标任务右侧的 `修改`，即可进入编辑表单。

### 6.2 指定任务名

发送：

```text
修改任务 喝水
```

或：

```text
编辑任务 喝水
```

当任务名唯一匹配时，机器人会直接打开编辑表单。

如果同名任务不止一个，系统会要求进一步确认，不会静默修改第一条记录。

### 6.3 编辑表单字段

编辑卡片支持修改：

- 任务名。
- 优先级。
- 状态。
- 进度。
- 阻塞原因。
- 标签。
- 开始时间。
- 截止时间。

填写完成后点击 `保存修改`。

从“选择要修改的任务”卡片进入编辑时，系统会按当前点击者筛选其负责的任务。普通使用者只应修改自己负责的任务；更严格的全入口权限收口仍应在后续版本继续完善。

### 6.4 直接修改状态

示例：

```text
修改任务 喝水 状态为阻塞中
```

```text
修改任务 喝水 状态为进行中
```

```text
修改任务 喝水 状态为已完成
```

状态修改同样需要先确认再写入。

### 6.5 可用任务状态

当前任务状态包括：

```text
未开始
进行中
阻塞中
已完成
已延期
```

用户口头说“延期中”时，系统内部统一使用现有枚举“已延期”。

## 7. 删除任务

发送：

```text
删除任务 喝水
```

也可以发送：

```text
删掉任务 喝水
```

```text
移除任务 喝水
```

删除属于不可恢复操作，因此机器人会先发送确认预览。

请确认任务名和负责人无误后再点击 `确认`。

如果匹配到多个同名任务，系统不会自动删除，需要先明确目标任务。

## 8. 每日任务盘点

### 8.1 发送时间

服务持续运行时，每天 18:00 按上海时区执行任务盘点。

如果服务在 18:00 没有运行，当天定时任务不会自动补发，除非管理员手动触发。

### 8.2 负责人卡片

任务负责人会收到“每日任务盘点”卡片。每条任务提供四个操作：

- `完成`：将任务标记为已完成。
- `继续`：保持任务状态不变，表示继续处理。
- `阻塞`：填写阻塞原因后，将任务改为阻塞中。
- `延期`：填写延期原因后，将任务改为已延期。

`阻塞` 和 `延期` 必须填写原因。

系统会在执行写入前重新校验点击者是否仍然是该任务负责人，避免任务负责人变化后旧卡片继续生效。

### 8.3 Leader 汇总

Leader 会收到“今日截止未完成任务”汇总卡片。

Leader 卡片为只读模式：

- 不包含任务操作按钮。
- 不允许代替负责人修改任务。
- 不包含员工聊天正文或聊天总结。

### 8.4 重复发送保护

同一天重复运行盘点时，系统会根据已保存的发送状态避免向同一接收者重复发送已经成功的卡片。

单个接收者发送失败不会阻断其他人的卡片。

## 9. 聊天总结

### 9.1 当前开放范围

当前部署采用单用户本机 `lark-cli` 试点模式，只允许预先配置的一名用户使用聊天总结。

其他用户发送总结指令时会收到：

```text
当前聊天总结试点只允许指定用户使用。
```

多人正式使用需要切换为每名用户独立 OAuth 授权模式，不能让多人共用本机 CLI 用户身份。

### 9.2 总结今天的聊天

在私聊中发送：

```text
总结今天的聊天
```

也可以发送：

```text
总结今日消息
```

机器人会先发送“聊天总结”处理中卡片，然后在后台读取当天文本消息并更新同一张卡片。

真实请求通常需要几十秒，消息较多时可能接近两分钟。请等待卡片从“聊天总结”更新为“聊天总结完成”，不要连续重复发送同一指令。

### 9.3 总结指定日期范围

示例：

```text
总结 2026-07-01 到 2026-07-15 的聊天
```

```text
总结 2026年7月1日 到 2026年7月15日 的消息
```

必须提供开始和结束日期。

日期按上海时区解释：

```text
开始日期 00:00:00
结束日期 23:59:59
```

开始日期不能晚于结束日期。

### 9.4 摘要内容

摘要按以下栏目输出：

- 重点信息。
- 已确认决策。
- 待办事项。
- 风险与待确认项。
- 相关人员。

空栏目不会展示。

发送者优先显示飞书姓名；机器人显示“智能客服”；无法读取姓名时显示“未知成员”，不会展示 `ou_...` 或 `cli_...` 内部标识。

### 9.5 数据范围和隐私

聊天总结只处理请求者当前读取身份有权访问的文本消息。

系统不会：

- 解析图片、文件、音频和视频内容。
- 将聊天原文写入任务 Base。
- 将聊天原文写入普通运行日志。
- 把私人摘要发送给 Leader 或其他用户。
- 自动创建模型识别出的任务。

摘要底层具备生成任务草稿候选的能力，但当前聊天总结结果只展示摘要正文，尚未提供完整的草稿确认入口。需要创建任务时，请继续使用任务创建流程并完成确认。

### 9.6 OAuth 模式说明

如果管理员将服务切换为多人 OAuth 模式，未授权用户首次请求时会收到授权链接。

用户完成授权后，需要重新发送原总结指令。

用户 Token 会使用 AES-256-GCM 加密保存。用户撤销飞书授权或 Token 刷新失败后，系统会停止读取并要求重新授权。

## 10. 常见提示及处理方法

### 10.1 “当前知识库暂无此信息”

含义：没有检索到足够相关的已发布知识。

处理：

- 换一种更明确的表达重新提问。
- 发送 `需要回访：你的问题` 请求人工跟进。
- 由知识库管理员补充并发布知识。

### 10.2 “暂时无法回答，请稍后重试”

含义：MiniMax、网络或消息处理发生临时错误。

处理：等待片刻后重新发送一次。若持续发生，请联系管理员检查错误日志。

### 10.3 “没有找到匹配的任务”

可能原因：

- 任务名不准确。
- 任务不属于当前负责人。
- 任务已被删除。
- 任务状态不在当前筛选范围。

处理：先发送 `查看我的任务`，确认实际任务名和状态。

### 10.4 “无法唯一确定负责人”

含义：成员表中没有找到该姓名，或存在多个同名成员。

处理：使用成员表中的完整显示名，或请管理员检查 Members 表。

### 10.5 “当前聊天总结试点只允许指定用户使用”

含义：当前仍为单用户试点，发送者不是配置的允许用户。

处理：联系管理员申请试点资格，或等待多人 OAuth 版本上线。

### 10.6 聊天总结一直停留在处理中

处理：

1. 先等待最多两分钟。
2. 不要连续重复发送。
3. 超过两分钟后重新发送一次。
4. 仍失败时请管理员检查 `.data/bot.err.log`。

### 10.7 卡片按钮点击后没有变化

可能原因：

- 卡片已过期。
- 任务已删除或负责人已变化。
- 飞书卡片回调权限或长连接异常。
- 后台进程未运行。

处理：重新发送任务查询或修改指令，获取最新卡片。

## 11. 使用建议

为了提高识别准确率：

- 任务名尽量具体，避免多个任务都叫“测试”或“喝水”。
- 修改和删除时写出完整任务名。
- 日期使用“今天”“明天”或完整日期。
- 任务阻塞和延期时填写明确原因。
- 知识问答一次只问一个主题。
- 聊天总结不要在同一时间连续提交多次。

推荐任务名：

```text
完成客服机器人回归测试
```

不推荐任务名：

```text
测试
```

## 12. 管理员快速启动

### 12.1 前置条件

- Node.js 20 或更高版本。
- 已启用机器人能力的飞书企业自建应用。
- 飞书事件订阅使用长连接。
- 已订阅 `im.message.receive_v1`。
- 已启用 `card.action.trigger`。
- 已开通机器人消息、Base、Card 2.0 等相关权限。
- MiniMax API Key。
- SiliconFlow API Key。
- 知识 Base、任务 Base 和成员表。

### 12.2 安装

```bash
npm install
cp .env.example .env
```

只在本地 `.env` 中填写真实配置。

禁止：

- 将 `.env` 提交到 Git。
- 将 App Secret、API Key 或用户 Token 写入文档。
- 在群聊中发送真实密钥。

### 12.3 基础配置

配置项说明见 `.env.example`，至少需要填写：

```dotenv
FEISHU_APP_ID=
FEISHU_APP_SECRET=
MINIMAX_API_KEY=
FEISHU_KNOWLEDGE_BASE_TOKEN=
FEISHU_TASK_BASE_TOKEN=
FEISHU_KNOWLEDGE_TABLE_ID=
FEISHU_QUESTIONS_TABLE_ID=
FEISHU_TASKS_TABLE_ID=
FEISHU_MEMBERS_TABLE_ID=
SILICONFLOW_API_KEY=
```

如暂不启用聊天总结：

```dotenv
ENABLE_CHAT_SUMMARY=false
```

单用户本机试点：

```dotenv
ENABLE_CHAT_SUMMARY=true
CHAT_HISTORY_PROVIDER=lark-cli
ALLOWED_CHAT_SUMMARY_OPEN_ID=<允许使用者的open_id>
LARK_CLI_PATH=lark-cli
```

多人 OAuth 部署请参考：

- `docs/superpowers/plans/2026-07-15-multi-user-chat-summary-implementation.md`

### 12.4 测试与启动

```bash
npm test
npm start
```

看到飞书 WS Client ready 日志后，再进行真实消息测试。

### 12.5 当前 Mac 托管服务

当前本机部署使用 `launchd` 服务：

```text
com.tjc.feishu-kefu-bot
```

重新加载最新代码：

```bash
launchctl kickstart -k gui/$(id -u)/com.tjc.feishu-kefu-bot
```

不要同时手动运行第二个 `node src/index.js`，否则可能形成重复实例并重复消费飞书事件。

检查实例：

```bash
ps -axo pid,ppid,lstart,command | rg '[n]ode src/index\.js'
```

预期只存在一个 Node 实例。

### 12.6 日志位置

当前本机日志：

```text
.data/bot.out.log
.data/bot.err.log
```

查看最近错误：

```bash
tail -n 100 .data/bot.err.log
```

日志不得主动打印：

- App Secret。
- MiniMax API Key。
- access token。
- refresh token。
- OAuth code。
- 完整聊天正文。

### 12.7 关闭聊天总结

设置：

```dotenv
ENABLE_CHAT_SUMMARY=false
```

然后重启服务。

关闭聊天总结不应影响：

- 知识客服。
- 任务创建和修改。
- 每日任务盘点。
- Leader 汇总。

## 13. 管理员验收清单

### 13.1 客服问答

- 私聊发送“你好”能收到回复。
- 群聊不 `@机器人` 时保持沉默。
- 群聊 `@机器人` 后能回复。
- 未命中知识时进入安全兜底，不编造制度。

### 13.2 任务管理

- `创建任务 喝水` 返回确认卡片。
- 确认后 Base 只新增一次。
- `查看我的任务` 返回任务卡片。
- `修改任务` 返回可编辑任务选择卡。
- 点击任务后进入编辑表单。
- 非负责人不能通过旧卡片修改任务。
- 删除任务必须二次确认。

### 13.3 每日盘点

- 负责人收到带操作按钮的卡片。
- Leader 只收到无按钮汇总。
- 阻塞和延期必须填写原因。
- 同一天重复运行不会重复发送已成功卡片。

### 13.4 聊天总结

- 允许用户发送 `总结今天的聊天` 后收到处理中卡片。
- 卡片最终更新为中文分节摘要。
- 摘要不包含 `ou_...` 或 `cli_...`。
- 非允许用户不能触发 CLI 读取。
- 原始聊天正文不进入 Base 和普通日志。

### 13.5 回归测试

```bash
npm test
```

当前基线：173 项测试全部通过。

## 14. 安全与隐私原则

1. 机器人只能使用已经授权的权限读取数据。
2. 多人聊天总结必须使用每名用户独立 OAuth Token。
3. 不允许公共员工账号或单个 CLI 用户身份替多人读取聊天。
4. 聊天原文不写入 Base、任务记录或普通日志。
5. 摘要只返回给发起请求的用户本人。
6. Leader 汇总不包含聊天正文或私人摘要。
7. 写任务、删任务和任务草稿都需要本人确认。
8. `.env`、`.data/` 中的 Token 和状态文件不得提交 Git。

## 15. 当前能力边界

当前版本不包含：

- 图片和文件理解。
- 语音或视频转写。
- 自动发布知识。
- 工单系统。
- 管理后台。
- 多实例高可用。
